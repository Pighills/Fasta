# T-08 · CSP och bort med inline-händelser (Claude Code, 2026-09-27)

## Vad ändrades
- `vercel.json`: nytt huvud `Content-Security-Policy` exakt enligt arbetsbeskrivningen. `script-src 'self'` (ingen `unsafe-inline`/`unsafe-eval`), `'unsafe-inline'` bara för stilar. Övriga säkerhetshuvuden kvar.
- Alla 28 `onclick`/`onchange` i `index.html` och `js/` ersatta med `data-action` + en gemensam klick- och ändringslyssnare i `js/app.js`.
- Inget ligger längre på `window` (tidigare `state`, `setView`, `startFast` m.fl.). `history.js`, `learn.js` och `timer.js` importerar funktionerna direkt i stället.
- Avbryt-knappen i bekräftelserutan och notisraden får sina lyssnare i JS.
- Dubbelberoendet `actions.js` ↔ `modals.js` behövde inte brytas (fungerar, ingen ändring).
- Nytt test `tests/csp.test.mjs`: inga inline-händelser i HTML/JS och CSP-huvudet finns med `script-src 'self'`.

## Var i appen det syns
Ingenstans – allt ska se ut och fungera som förut. Skillnaden är ett extra skydd: webbläsaren kör bara JavaScript från appens egna filer.

## Inte testat
- Export och import klickades inte (export laddar ner en fil, import öppnar filväljaren). Koden använder `Blob`, `createObjectURL` och `navigator.share`, som CSP:n inte stoppar.
- Trenderna i Historik (kräver check-in-data). Koden där ändrades inte och använde redan `addEventListener`.
- `integritet.html` ligger inte på main än (T-25, PR #46). Den har inget inline-JS och inga externa filer; testa med CSP vid publiceringen.
- Riktig telefon/offline.

## Risker
- Skulle någon knapp ha missats slutar den svara. Testet i `tests/csp.test.mjs` fångar nya inline-händelser.
- Efter publicering: kontrollera huvudet live med curl.
